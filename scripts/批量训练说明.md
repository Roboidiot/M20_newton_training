# 按组顺序训练

入口：`scripts/train_batch.py`；示例配置：`scripts/train_batches.json`。

该脚本使用当前 Python 环境，通过原生 `python -m isaaclab train --rl_library rsl_rl` 启动训练。
每组使用独立进程，上一组退出后才启动下一组，避免多个训练同时占用显卡。
支持本项目的 Flat、Walk、Rough、Stand、Sand、WalkOnSand、WalkOnSandProxy 任务。
脚本不修改任务源文件、奖励函数、网络结构或 rsl_rl 库。

## 1. 修改配置

在项目根目录打开 `scripts/train_batches.json`。

- `defaults`：所有组共同使用的参数。
- `runs`：按数组顺序训练；每组必须有唯一的 `name`，仅使用英文字母、数字、下划线和短横线。
- 每组先继承 `defaults`，再用自身参数覆盖。`reward_weights` 和 `overrides` 按键合并。
- **组与组之间不继承权重**。第二组没有指定的奖励，使用公共配置或任务源文件中的默认值，不沿用第一组修改。
- 没有列出的奖励维持任务默认配置。权重为 `0` 表示禁用；正负号保持该奖励原本的含义。

当前配置（2026-11-08）是6组 WalkOnSandProxy 对比实验：以此前group2、group4的奖励参数为两套基线，
各比较三种策略起点。每组2048个环境、训练3000次PPO迭代，随机种子42，按表中顺序独立训练。

| 组名 | 奖励基线 | 前向迈步权重 | 线速度跟踪权重 | 起点 |
| --- | --- | ---: | ---: | --- |
| group_01_g2_12500 | 原group2 | 100 | 5 | 原group2的model_12500.pt |
| group_02_g2_height062 | 原group2 | 100 | 5 | height0.62deg15/model_11000.pt |
| group_03_g2_scratch | 原group2 | 100 | 5 | 无checkpoint，从零训练 |
| group_04_g4_12500 | 原group4 | 50 | 10 | 原group4的model_12500.pt |
| group_05_g4_height062 | 原group4 | 50 | 10 | height0.62deg15/model_11000.pt |
| group_06_g4_scratch | 原group4 | 50 | 10 | 无checkpoint，从零训练 |

完整起点路径（以项目根目录为基准）：

```text
group2: logs/rsl_rl/deeprobotics_m20_walk_on_sand_proxy/2026-11-07_21-23-23_198a52_02_group_02/model_12500.pt
group4: logs/rsl_rl/deeprobotics_m20_walk_on_sand_proxy/2026-11-07_21-23-23_198a52_04_group_04/model_12500.pt
height: logs/rsl_rl/deeprobotics_m20_walk_on_sand_proxy/height0.62deg15/model_11000.pt
```

`feet_forward_step`和`track_lin_vel_xy_exp`在每组中显式设置；其余奖励、指令、初始化及PPO参数
使用当前任务源码默认值，并非恢复checkpoint训练时的历史配置。公共`reward_weights`、`overrides`为空。
所有组均设置`resume_optimizer_state=false`：有checkpoint时加载Actor、Critic和策略探索标准差，
不恢复优化器状态；`checkpoint=null`不传递`--checkpoint`，使用新初始化网络。
各组不加载前一组训练结果。加载checkpoint时迭代编号继续累计，3000表示额外更新轮数。

当前共享沙地配置中，抬升和前向迈步的连续卸载时间下限为0.5s，腾空时间奖励阈值为0.5s，
50Hz下对应25个未接触采样；短腾空惩罚保留。当前禁用的沙面净空、抬升一致性和旧迈步完成项也设置0.5s下限，
保持禁用。相位奖励沿用原接触判定和3s统计窗口，不增加时长门槛。其他奖励权重沿用源码；以后修改源码，
这些未覆盖参数也会随之变化。
机身高度低于或等于环境原点上方0.60m时重置；名义沙面为0.30m，因此对应机身距沙面0.30m。

启动整批：

```bash
uv run python scripts/train_batch.py --config scripts/train_batches.json
```

只训练某一组：

```bash
uv run python scripts/train_batch.py --config scripts/train_batches.json --only group_01_g2_12500
```

观察速度误差、逐脚`Metrics/forward_steps/*`、`Metrics/foot_forces/*_fz_mean`和重置频率，
并用play检查实际前进、抬腿和下陷。不同起点可能有不同的探索标准差，不能仅按总奖励高低判断策略优劣。

常用字段：

| 字段 | 含义 |
| --- | --- |
| `task` | 完整注册任务名，例如 `M20NewtonTraining-M20-M20-WalkOnSandProxy` |
| `physics` | 物理预设。Proxy/Walk 等用 `newton_mjwarp`；MPM 沙地任务用 `newton_sand` |
| `num_envs` | 并行环境数量，必须为正整数 |
| `max_iterations` | 本组执行的 PPO 迭代数，必须为正整数；加载 checkpoint 时也是额外训练轮数 |
| `seed` | 随机种子。相同种子便于比较，但不保证 GPU 仿真逐位确定 |
| `checkpoint` | `null` 从零训练；本地 checkpoint 路径；或 `"previous"` 接上一组训练 |
| `resume_optimizer_state` | 是否恢复 checkpoint 中的优化器状态，默认 `false` |
| `logger` | 默认 `tensorboard` |
| `viz` | 默认 `none`；需要观察可设置 `newton` |
| `device` | 可选，例如 `cuda:0` |
| `experiment_name` | 可选，覆盖原生训练日志的实验目录名称 |
| `agent` | 可选，原生 agent 配置入口名，默认使用 RSL-RL 入口 |
| `reward_weights` | 奖励项名称到权重的映射，名称与任务配置和 TensorBoard 奖励槽位一致 |
| `overrides` | 原生 Hydra 的 `env.*`、`agent.*` 参数覆盖，用于奖励参数、速度范围和 PPO 参数等 |

不同任务可以写在不同组中，例如：

```json
{
  "name": "mpm_test",
  "task": "M20NewtonTraining-M20-M20-WalkOnSand",
  "physics": "newton_sand",
  "num_envs": 4,
  "max_iterations": 500,
  "reward_weights": {
    "feet_sand_clearance": 40.0
  }
}
```

上面的例子需要放进完整配置的 `runs` 数组中。切换任务时同步检查物理预设、并行数和该任务是否有对应奖励。
MPM 的计算开销明显高于代理模型，不应直接照搬 2048 个并行环境。

## 2. 预览和检查

在项目根目录执行：

```bash
# 仅显示命令和本组明确设置的权重，不导入仿真库、不启动训练、不创建输出目录。
.venv/bin/python scripts/train_batch.py --config scripts/train_batches.json --dry-run

# 使用真实任务配置和原生解析器检查任务、奖励名称、物理预设和 Hydra 参数；不启动仿真。
.venv/bin/python scripts/train_batch.py --config scripts/train_batches.json --validate-only
```

`--validate-only` 会创建批次输出目录，记录合并后的配置与最终生效的奖励权重。
正常训练前也会自动检查所有选中的组；第二组配置有错时，不会先浪费时间训练第一组。
配置检查不创建机器人和求解器，因此不能代替实际运行对显存、物理稳定性、传感器绑定等的验证。

## 3. 开始训练

```bash
# 按配置顺序训练所有组。
.venv/bin/python scripts/train_batch.py --config scripts/train_batches.json

# 只训练指定组，仍按 JSON 中的顺序执行。
.venv/bin/python scripts/train_batch.py --config scripts/train_batches.json --only group_02_g2_height062

# 某组训练失败后继续后面的独立实验；默认遇到失败就停止。
.venv/bin/python scripts/train_batch.py --config scripts/train_batches.json --continue-on-error
```

按 `Ctrl+C` 会中断当前训练，并停止整个队列，不会启动下一组。
两组均从零训练时，将公共 `checkpoint` 设为 `null` 即可。
要从同一个 Walk 策略分别比较多组权重，将公共 checkpoint 改为：

```json
"checkpoint": "logs/rsl_rl/deeprobotics_m20_walk/2026-10-21_19-37-26/model_9999.pt"
```

所有组都会加载同一个 checkpoint，彼此独立。checkpoint 相对路径以**项目根目录**为基准，
与配置文件存放位置无关；也可以使用绝对路径或以 `~` 开头的路径。
脚本不接受 `latest`/`best` 选择器，以避免批次运行时意外选择到刚完成的其他实验。

## 4. 按阶段连续训练

需要第一组训练结束后，第二组接着第一组的策略训练时，在第二组中写：

```json
{
  "name": "group_02",
  "checkpoint": "previous",
  "resume_optimizer_state": false,
  "reward_weights": {
    "feet_sand_clearance": 40.0
  }
}
```

脚本只从**紧邻的上一组成功训练的日志目录**选择编号最大的 `model_*.pt`，不会全局搜索最新模型。
上一组失败或没有保存 checkpoint 时，依赖它的下一组不能启动；`--continue-on-error` 也不会回退使用更早组的模型。
第一组选中的实验不能设置 `previous`。跨任务接续时，观测、动作和网络结构仍须兼容。

加载 checkpoint 会保留原生 RSL-RL 的迭代编号，不会从零重新计数。
`resume_optimizer_state=false` 使用新的优化器和配置学习率，但仍加载 actor、critic、迭代信息以及策略的探索标准差。
如果需要保持优化器动量和 checkpoint 中的学习率，设置为 `true`。

## 5. 修改速度范围、奖励函数参数和 PPO 参数

在公共配置或某组内增加 `overrides`，例如：

```json
"overrides": {
  "env.commands.base_velocity.ranges.lin_vel_x": [0.15, 0.25],
  "env.commands.base_velocity.ranges.lin_vel_y": [0.0, 0.0],
  "env.commands.base_velocity.ranges.ang_vel_z": [0.0, 0.0],
  "env.commands.base_velocity.min_abs_command": 0.15,
  "env.rewards.feet_forward_step.params.target_stride": 0.20,
  "agent.algorithm.learning_rate": 0.0003,
  "agent.algorithm.entropy_coef": 0.01
}
```

`min_abs_command` 等字段只存在于使用单轴指令采样器的任务，不能直接套用所有任务。
`env.*`、`agent.*` 覆盖在任务初始化和批次权重设置后由原生 Hydra 应用；CLI 中明确给出的
`seed`、`device` 等参数可能进一步覆盖相应 Hydra 字段，应优先使用脚本的同名顶层选项。
`num_envs`、`max_iterations`、`experiment_name` 用顶层选项；奖励权重统一放进 `reward_weights`。

## 6. 零权重奖励的处理

项目原本在配置初始化时把零权重奖励设成 `None`，直接用命令行将它们改成非零可能失败。
脚本使用原生 `--external_callback` 钩子，仅在当前训练子进程中暂缓项目的奖励清理：

1. 完整构造原任务配置，保留任务对奖励函数、参数及接触力来源的绑定。
2. 应用本组 `reward_weights`。
3. 将最终权重为零的项移除。
4. 继续原生配置解析和训练。

因此可以重新启用任务中有完整定义、仅因零权重被禁用的奖励；
显式删除、没有对应函数定义，或依赖不存在传感器的项，仍需先完善任务配置。
暂缓操作会在构造配置后恢复，不改写训练源文件，也不影响其他进程或平时直接使用的 `isaaclab train`。

## 7. 输出目录和 TensorBoard

批次信息默认保存在：

```text
output/training_batches/<时间_随机标识>/
├── config.json                 # 本次输入配置快照
├── manifest.json               # 各组状态、实际训练目录、checkpoint、退出码
├── 01_group_01/
│   ├── requested.json          # 合并后的组参数、实际命令、实际加载的 checkpoint
│   ├── validation.json         # 检查后的启用奖励及权重、环境数、训练目录
│   ├── validation.log
│   └── train.log               # 同步显示在终端的完整控制台输出
└── 02_group_02/
    └── ...
```

原生训练产物保持在：

```text
logs/rsl_rl/<任务默认实验名或 experiment_name>/<批次时间_标识_组号>_<组名>/
├── params/
├── events.out.tfevents.*
└── model_*.pt
```

每组拥有独立 TensorBoard 曲线和 checkpoint。可以同时比较所有 Proxy 实验：

```bash
.venv/bin/tensorboard --logdir logs/rsl_rl/deeprobotics_m20_walk_on_sand_proxy --port 6006
```

也可以通过 `--output-dir output/training_batches/my_test_01` 指定一个尚不存在的批次目录。
输出和日志均在现有 `.gitignore` 忽略范围内；脚本、示例配置和本文档可以提交 Git。
